# design-sync NOTES — Rigatti Design System (shadcn/ui)

This repo is a full-stack SaaS app, not a published component library. The synced
"design system" is the **shadcn/ui** set under `frontend/src/components/ui/`, themed
with the project's Tailwind tokens. Shape = `package`, built in **no-dist / custom
entry** mode (Vite builds the app, not a component lib).

## Build recipe (run before the converter — order matters)

All commands run with `frontend/` deps and the staged `.ds-sync/` deps.

1. **Tailwind CSS precompile** → `frontend/.ds-tailwind.css` (this is `cfg.cssEntry`).
   The converter copies a *static* stylesheet; it does not run Tailwind. Content
   covers the ui components AND `.design-sync/previews/`.
   ```
   cd frontend && node_modules/.bin/tailwindcss -c tailwind.ds.config.cjs \
     -i src/index.css -o .ds-tailwind.css
   ```
   `tailwind.ds.config.cjs` **mirrors** `theme.extend` from `tailwind.config.ts` —
   keep in sync if that file changes. Re-run this whenever previews add new classes.

2. **Type contracts** → `frontend/index.d.ts` (drives component discovery AND prop
   extraction). Generated by tsup from `frontend/ds-dts-entry.tsx` (the 48 top-level
   components only).
   ```
   cd frontend && NODE_PATH=<repo>/.ds-sync/node_modules \
     ../.ds-sync/node_modules/.bin/tsup ds-dts-entry.tsx --dts --format esm \
     --out-dir types-dts --tsconfig tsconfig.app.json
   cp types-dts/ds-dts-entry.d.ts index.d.ts && rm -rf types-dts
   ```

3. **Converter build + validate** (from repo root):
   ```
   node .ds-sync/package-build.mjs --config .design-sync/config.json \
     --node-modules frontend/node_modules --entry frontend/ds-entry.tsx --out ./ds-bundle
   node .ds-sync/package-validate.mjs ./ds-bundle
   ```

## Why two entries
- `frontend/ds-entry.tsx` — `export *` of every ui file → the **JS bundle** (all
  sub-components on `window.RigattiUI` for preview composition).
- `frontend/ds-dts-entry.tsx` — only the 48 top-level components → `index.d.ts`,
  which the converter reads for discovery + props. Without this split, discovery
  picks up all ~246 exports (a card per sub-component).

## Gotchas discovered
- **tsup needs `typescript@5.x`** in `.ds-sync` — the `latest`/`6.x`/`7.0` line errors
  `TS5101 baseUrl deprecated`. Pinned `typescript@5.6.3`.
- **The dts must NOT be a dotfile** — fast-glob in the converter's dts loader skips
  dotfiles, so `.ds-entry.d.ts` parsed 0 files. Entry filenames have no leading dot.
- **`index.d.ts` must sit at `frontend/` root** (no `pkgJson.types`): `findTypesRoot`
  falls back to the package dir and `loadDts`'s entry defaults to `index.d.ts`. This
  is what makes the call-signature fallback resolve props for inline-typed
  (Radix-wrapper) components like Accordion/Dialog/Select.
- **Two `Toaster` + `toast` collisions** (toaster.tsx vs sonner.tsx): disambiguated
  in both entries — Radix `Toaster`, sonner exposed as `SonnerToaster`.

## Grouping
48 components are grouped via 7 shared category stubs in
`.design-sync/group-docs/<group>.md` (frontmatter `category:` only, empty body →
the synthesized `.prompt.md` is preserved). `cfg.docsMap` points each component at
its group stub. Adding a new component requires a `docsMap` entry.

## Known render warns (triaged, expected)
- Avatar / Progress / Slider floor cards render blank (<5KB PNG) because the bare
  component has no children/value. Resolved by authoring their previews.

## Authoring tips (from preview waves)
- Static captures: use **uncontrolled** props (`defaultChecked`, `defaultValue`, `open`) to
  avoid controlled-without-onChange React warnings.
- Width-`full` roots (Slider, Progress, Input) need a fixed-width wrapper (e.g. `w-[280px]`)
  to show at a sensible size in the card.
- Vertical `Separator` needs an explicit parent height (e.g. a `h-6` flex row).
- `ChartTooltip`/`Tooltip`/menu hovers don't show in static shots — the bars/axis/trigger
  carry the cell. Not a defect.
- Overlays render open via the root `open` prop; their `cardMode:single` + viewport are set
  in `cfg.overrides`.
- **Sidebar**: use `<Sidebar collapsible="none">` inside `SidebarProvider` + a fixed-height
  wrapper — the default `fixed h-svh hidden md:block` Sidebar renders blank/overflowing in a
  static card.
- **NavigationMenu**: force one panel open with `defaultValue` on Root + matching `value` on
  the item; use `navigationMenuTriggerStyle()` for plain sibling links.
- **Toast / Toaster** (Radix): render a static `<ToastProvider><Toast open>…<ToastViewport/>`;
  the viewport is `fixed`, so a `transform` wrapper (e.g. `style={{transform:"translateZ(0)"}}`)
  on the container makes the fixed viewport render inside the card.
- **ContextMenu**: right-click only — can't open statically; the card shows a styled trigger
  area. **SonnerToaster**: runtime-only (no static API) — ships as a floor card by design.

## Re-sync risks (watch-list for the next run)
- **buildCmd is NOT set** — the driver (`resync.mjs`) only runs `package-build`. You MUST run
  the two prereqs manually first, in order: (1) the Tailwind precompile, (2) the tsup dts →
  `frontend/index.d.ts`. See "Build recipe" above. Skipping (1) → stale/unstyled CSS;
  skipping (2) → empty prop contracts + 246-component discovery.
- **`tailwind.ds.config.cjs` mirrors `frontend/tailwind.config.ts`** — if the app's theme
  tokens/colors change, update the mirror or tokens drift from the app.
- **`ds-dts-entry.tsx` is a hand-maintained 48-component list** — adding/removing a shadcn
  component requires updating BOTH `ds-entry.tsx` (export *) and `ds-dts-entry.tsx` (named
  export) plus a `componentSrcMap` + `docsMap` entry; otherwise it won't get a card.
- **pravatar/picsum image URLs** in Avatar/AspectRatio previews are network-fetched at capture
  time — offline captures will show broken images.
- **SonnerToaster** ships as a floor card by design (runtime-only). Re-authoring won't help
  unless Sonner gains a static render path.
- TS pinned at `typescript@5.6.3` in `.ds-sync` — a newer major breaks tsup dts (baseUrl).

## Cosmetic .d.ts noise
- Emitted `*Props` reference `React$1.CSSProperties` (tsup's bundled React alias) and
  a verbose `ref?:` type. Functional, read fine by the design agent; not worth
  post-processing.
